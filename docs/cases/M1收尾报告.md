## 一、样本外验证（①）—— **h=252 必须降级**

把 91 个调仓切成**前半 2019-2022（48 期）/ 后半 2023-2026（32 期）**，
绝对门槛仍取腰斩 −50%：

| h | 前半 | 后半 | 判定 |
|---|---|---|---|
| 21 | −0.001 (t=−2.22) | −0.001 (t=−2.57) | 同向，但绝对率仅 0.1%，样本太稀 |
| 63 | −0.003 (**t=−4.05**) | −0.007 (**t=−3.64**) | ✅ **两段都稳** |
| 126 | −0.009 (**t=−4.89**) | −0.017 (**t=−3.32**) | ✅ **两段都稳** |
| 252 | −0.004 (**t=−0.69**) | −0.022 (**t=−3.51**) | ❌ **前半不成立** |

**第二次自我修正**：上一轮把 h=252 的 t=−3.10 写成了结论，
样本外一验证就露馅 —— 那是后半段撑起来的。**h=63/126 才是能站住的那个**
（两段独立样本 t 在 −3.3 ~ −4.9，量级同向）。U 型在两段都成立。

> **ROE 的收敛表述**：在 3~6 个月持有期上，最低分位的腰斩概率约为最高分位的
> **3 倍**（1.7% vs 0.5%），两个独立子样本一致；12 个月口径**不成立**；
> ROE 对收益没有预测力。

## 三、事件研究 `analysis/event.py`（③）

```python
w = acna.align_event_windows(prices, events, calendar,
                             window=(-5, 20), base_day=0, benchmark='000300')
print(w.summary())          # 逐相对日：均值 / 胜率 / t_naive / t_ct
acna.event_path_by_group(w, 'surprise', quantiles=5)   # PEAD 形态
```

产生 ``ret`` / ``cum_ret`` / ``car`` / ``abn_ret``；``base_day`` 默认 **0**
（事件日收盘为基准）→ ``car[+1..+N]`` 就是公告后漂移。

### ⚠️ 事件聚集时朴素 t 会虚高

同一段时间里密集发生的事件（财报季）窗口互相重叠，**横截面 t 会严重高估显著性**。
所以 `event_summary` 同时给 ``t_naive``（横截面）与
``t_ct``（**日历时间组合法**：把当天所有事件的均值当一条时间序列，再上 Newey-West）。

防线 5 的构造测试：120 个事件挤在 3 天里、当日共同效应 [+10%, 0%, +5%] ——
实测 ``|t_naive| > 5 × |t_ct|``，``t_naive`` 超过 8 而 ``t_ct`` 不到 5。

### 顺手抓到一个真 bug

第一版用 ``pct_change()`` 算日收益 —— **pandas 默认前值填充**，
把停牌日伪装成"0 收益"，于是窗口看着完整、其实中间停了两周。
改成 ``pct_change(fill_method=None)`` 后停牌 → NaN → 该事件按 ``missing_price``
如实剔除。**测试写出来的当天就抓到了**（`test_ledger_records_drops`）。

## 四、RRE 排名熵稳定性 `inference/rank_entropy.py`（③）

```python
acna.rank_stability(factor)        # RRE ∈ [0,1]，1 = 排名结构完全不变
acna.rank_entropy_summary(factor)  # + 分布熵、退化/噪声/不更新的自动提示
```

* **RRE** = 相邻两期"留在同一排名档位"的资产占比，归一化到 ``[0,1]``。
* **分布熵** = 对截面 z 分数等宽分箱后的香农熵（归一化）。

### 第一版写错了，记一笔

初版按**排名**分桶算直方图 —— 排名分桶后每期必然均匀，
于是熵恒等于 1、KL 恒等于 0、**RRE 恒等于 1**，什么都测不出来
（实测"每期独立随机"的因子也报 RRE = 1.0）。
改成**排名转移矩阵的对角线**后：完全不变 → 1.0，独立 → 0.0 ✅

> **分辨率提醒**：默认 ``bins=10`` 时最小步长 1/10，
> 中等自相关的因子读数也会偏小（实测秩自相关 0.43 → RRE ≈ 0.06）。
> 要更灵敏就调大 ``bins``。这一条写进了 docstring。

## 五、PFS 扰动鲁棒性 `inference/robustness.py`（③）

```python
acna.pfs(ic_series, n_draws=200, frac=0.8)          # ∈ [0,1]
acna.robustness_report(ic_series, fracs=(.5,.7,.9)) # 多组扰动并列展示
```

``PFS`` = 扰动后仍与基准**同号且幅度在容差内**的比例。三种扰动：
``subsample`` / ``bootstrap`` / ``drop_assets``（面板入口）。

### 它的语义必须写准（否则会误用）

实测：**纯噪声序列的 PFS 也能到 0.85** —— 因为"抽掉 20% 的期数"
对 100 期的均值本来就没多大影响。PFS 真正擅长抓的是另一种病：

> **结论靠少数几期（或少数极端样本）撑着 —— 抽掉那一期，符号就翻。**

构造验证（99 期小负 + 1 期巨大正，全样本均值翻正）：

| 指标 | 读数 | 含义 |
|---|---|---|
| `pfs` | **0.000** | 幅度完全不可复现 |
| `same_sign` | 0.85 | 符号多半还在（那期多数抽样里还在） |
| `p5` / `p95` | −0.010 / +0.009 | 扰动分布**跨过 0** |

**两个数一起看才不会被骗** —— 只看 `same_sign` 会以为结论很稳。

## 六、研究台账 `ledger/`（③）—— 本库的灵魂落地

>>> led.record(goal='roe', factor='roe', horizon=21, t=-1.42)
>>> led.n_trials('roe')          # 自动数出来的，不是猜的
>>> ok, msg = led.check_n_trials(claimed=3, goal='roe')
>>> ok                            # False：报了比台账少的数 = 低报校正基数

* **append-only JSONL**，可读、可 diff、可 git 管，不引数据库。
* ``n_trials`` 按 ``(goal, factor, horizon)`` **去重** ——
  同一个检验重跑十遍不算十个假设。
* ``threshold(goal)`` 给 Bonferroni |t| 门槛；**台账为空 → NaN**
  （没记录就没有门槛，不假装 1.96）。
* ``check_n_trials`` 专门抓**低报**：报的比台账少 → 不通过。
* ``fingerprint()`` 把"结论基于哪本台账"写进报告。
* 坏行跳过，整本台账不许因一行坏掉。
