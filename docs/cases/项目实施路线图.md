## 第一部分 · 已有结论盘点

### 1.1 实证分析（6 份报告，1,516 行 + 21 张图）

| 报告 | 核心结论 |
|---|---|
| `ROE因子分析报告.md` | 日频观测，IC 1D 0.0040 → 20D 0.0006，t_naive 1.40 → 0.16 |
| `ROE月度调仓分析报告.md` | 91 个月，RankIC(开盘) −0.0108 → −0.0593，`Q5−Q1` −0.67% → −7.28% |
| `FamaMacBeth截面回归报告.md` | **ROE 单变量 γ=−0.0021，加控制变量后翻正 +0.0003** |
| `事件研究报告_财报公告.md` | 财报信息 **1 个交易日内被完全定价**，第 +1 日见顶，之后反转 |
| `功能增补清单_基于因子投资书.md` | 对照石川书，缺 5 项 P0 能力 |

**贯穿性发现（立项理由）**：

> 财报信息在 **T+1 日内被完全定价** ⇒ ROE 这类季度财务因子，
> 在**月度周期**上**结构性地没有增量 alpha**。财务因子要靠**事件驱动**，不是周期调仓。

### 1.2 管线自证

| 对照 | RankIC | t |
|---|---|---|
| ROE | 0.0040 | 1.40 |
| **20 日动量（对照组）** | **−0.0388** | **−10.35** |

同一套管线，动量给出教科书级 A 股短期反转 → **管线是灵的，是 ROE 因子本身无效**。
alphalens 的 IC 与自算 IC **8/8 完全一致**（容差 1e-6）。

### 1.3 alphalens 缺陷清单（实测）

D1 非日频索引崩 / D2 列名错标 / D3 硬依赖绘图 / D4 重叠观测无修正（t 虚高 3–4 倍）/
D5 `dropna()` 一刀切 / D6 无涨跌停停牌 T+1 / D7 生存者偏差 / D8 无中性化 /
**D9 非日频下 `turnover`/`rank_autocorr` 静默返回 NaN** / **D10 零截面回归、零显著性检验**

### 1.4 设计结论

- **契约**：`(factor, prices)` → **`(factor, prices, calendar, tradability)`**，`prices` 改**长表**
- **六道防线**：契约校验 / 数据体检 / 不变量对账 / 等价性回归(1e-10) / 已知答案测试 / 稳健性报告
- **核心零绘图依赖**，只出 tidy DataFrame
- **协议 Apache 2.0**

## 第二部分 · 【v2 新增】竞品定位

外部文章提示了三个参考项目，我逐个核实了 README。**结论：方向被印证，但空位仍然空着。**

| 项目 | 是什么 | 协议 | 关键事实 |
|---|---|---|---|
| **zer0factor** | A 股因子**工作台**（生成→注册→存储→评估） | MIT | **评估层直接调用 Alphalens/Pyfolio** → 全盘继承 D1–D10 |
| **FactorHub** | 全栈**平台**（FastAPI + React + VectorBT） | **AGPL-3.0 + 商用需单独授权** | 有 IC/IR、单调性、换手；**无多重检验、无 FM 回归** |
| **FinHack** | 全流程框架（含动态复权回测） | — | 回测层做得好，分析层非重点 |

### 2.1 空位在哪

**三家都是"平台/工作台"，没有一家是"可对拍的验证内核"。**

- `zer0factor` 自己 README 里写明当前限制：
  > "`FactorFrame` 还没有暴露 **ST、停牌、上市天数、精确涨停**等字段。"

  → **这恰好是步骤 3 的全部内容。** 它把评估外包给 alphalens，等于把 D1–D10 一起继承了。

- `FactorHub` 功能面铺得很开，但**没有多重假设检验、没有 Fama-MacBeth**；
  且 **AGPL-3.0 明文禁止企业内部用于投资研究**，机构法务基本会直接否掉。

### 2.2 我们的差异化（三条，都是别人明确没有的）

| # | 差异化 | 谁没有 |
|---|---|---|
| 1 | **可对拍性** —— 退化配置下与 alphalens **1e-10 数值一致** | **全部没有**。没人做等价性回归 |
| 2 | **A 股制度正确性** —— ST / 停牌 / **精确涨停** / 新股 / 隔夜跳空分离 | zer0factor **自己承认缺** |
| 3 | **科学性** —— 多重检验 + 六道防线 + FM/Shanken | FactorHub 有前一半，**没有后一半** |

### 2.3 协议这步棋

`FactorHub` 用 **AGPL-3.0 + 商用授权**，`zer0factor` 用 MIT（但只做工作台不做内核）。

→ 我们选 **Apache 2.0** 的相对优势是**真实的**：有专利授权条款、允许闭源商用、
机构可以直接嵌进内部系统。**这在这个赛道里是个明确的空位。**

### 2.4 一条可能的落地路径

`zer0factor` 的评估层现在是 alphalens。**alphalens-cna 可以成为它的替换后端** ——
对我们是被采用，对它是修掉 D1–D10。**这比"再做一个平台"务实得多。**

**做什么**

**【v3 新增】FM 回归引擎选型：不依赖第三方包，自持内核 + 独立裁判**

外部文章建议"以 `fama_macbeth` 包作为底层回归引擎"。**核实后否决**：

| 核实项 | 结果 |
|---|---|
| PyPI `fama_macbeth` / `famamacbeth` | ❌ **双双 404** |
| GitHub `leoliu0/fama_macbeth` | 2 stars / 2 forks / 0 releases |
| 用法 | README 写"get the famamacbeth.py and" → **拷贝单个 .py 文件** |
| 作者自评 | *"The implementation is rather naive."* |
| 作者对发布的态度 | *"Ideally when it gets mature I can push it to PyPi."* |

若真要用现成包，应该是 `linearmodels.panel.model.FamaMacBeth`
（v7.0，Kevin Sheppard，原生 kernel covariance 即 NW + `from_formula`）。
**但仍不推荐当引擎**，四条理由：

1. **Shanken 修正两个包都没有** —— 无论如何要自己写，"省事"省不到关键处
2. **"封装接口层"本身就是全部工作量** —— alphalens 的 `factor_data` 是 long MultiIndex
   单因子，多因子 FM 需重新对齐；封装是主体，回归是零头
3. **FM 没有数值难点** —— 逐期 OLS + 时序均值/协方差；我们**已有跑通并产出报告的
   实现**（`run_fama_macbeth.py`，约 40 行 statsmodels）
4. **这个依赖是负债** —— 项目卖点是可对拍性（1e-10）；底层换成第三方包后，
   **对拍失败时进不去它内部定位**

**决策**：

```
主引擎   = 自持实现（statsmodels 做底层 OLS）    ← 可读、可测、可对拍
第二裁判 = linearmodels（可选依赖 extras[validate]） ← 仅用于交叉验证
```

> `linearmodels` 的价值**不是当引擎，而是当第二个裁判** —— 就像我们用 alphalens
> 对拍 IC 一样，用它独立对拍我们自己的 γ 与 NW t 值。
> **两个独立实现给出同一个数，才是可信的。**

**出口标准**
- 用本次 ROE/规模/换手数据跑通，**结果与手工实现一致**
- **FM 的 γ 与 NW t 值通过 `linearmodels` 独立复算**（可选依赖，CI 里跳过或装）
- **可证伪预测**：若"ROE 负向=规模混淆"成立，同一规模组内 ROE 单调性应消失

## 第五部分 · 【v2 核心修订】复权口径

### 5.1 实测：我们现在用的是「前复权」，而且是动态的

```
600519 贵州茅台
  2001-08-27   adj = 0.11716
  2016-08-25   adj = 0.810076   不复权 303.01 → 复权后 245.46
  2026-09-14   adj = 1.0        ← 最新端为 1
```

**adj = 1 在最新端 ⇒ 前复权（动态复权）。**

前复权的问题：**只要来了新数据，整段历史价格会被重新缩放。**
我们缓存的 `px_daily.parquet` 是"某一时刻的前复权快照"，所以：

| 影响面 | 后果 |
|---|---|
| 收益率计算 | ✅ **无影响** —— 前复权与后复权在同一面板内给出相同收益率 |
| **价格水平判定** | ❌ **全错** —— 涨跌停价、最小报价单位都依赖真实价格 |
| **可复现性** | ⚠️ 下月重跑，历史价格水平全变（收益率不变） |

### 5.2 缺陷实证：涨停价会差 23%

```
600519  2016-08-26 涨停价
  用原始价     算：round(303.01 × 1.1, 2) = 333.31   ✅ 正确
  用前复权价   算：round(245.46 × 1.1, 2) = 270.01   ❌ 差 63.30 元 (23%)
```

**v1 路线图的步骤 3 写的是 `round(prev_close × (1±ratio), 2)`，没规定 `prev_close` 用哪种价。
如果实现者顺手用了复权面板，涨跌停判定会全线失效 —— 而且是静默失效。**

### 5.3 v2 的解法：契约层强制「三价并存」

```
Prices 长表必须同时含：
  raw_*      原始不复权 OHLC        → 只用于「制度判定」（涨跌停价/报价单位/ST）
  adj_factor 复权因子               → 复权口径的唯一真相来源
  adj_*      复权价（由前两者导出）  → 只用于「收益计算」
```

**三条硬规则，写进契约校验：**
1. 任何**制度判定**（涨跌停、报价单位）**只允许读 `raw_*`**
2. 任何**收益计算**只允许读 `adj_*`
3. 只存复权价、不存原始价 + 因子 ⇒ **契约校验直接拒绝**（因为这等价于丢失了可复现性）

> **口径选择**：统一用 **后复权**（`adj_factor` 存累计后复权因子）。
> 两个独立来源都指向它 —— 外部文章明确推荐，`zer0factor` 的 `FactorSpec` 也写死 `adjust="hfq"`。
> 后复权价格水平与真实价同量纲，且**不随新数据回溯改变**。

## 第七部分 · 对外部文章的逐条评估

### 7.1 采纳（4 条）

| # | 建议 | 为什么采纳 |
|---|---|---|
| 1 | **复权口径必须显式建模，推荐后复权** | **触发 §5 整章修订，抓出一个静默失效的真 bug** |

| 4 | **截面样本数守卫（≥30）** | 分组/双重排序后容易触线，是真实风险 |

### 7.2 印证（2 条 —— 我们已经想到，它佐证了）

- **行业+市值中性化在分析之前做**，用截面回归取残差 → 与步骤 5 一致
- **信号日与交易日显式偏移、不要藏在 shift 里** → 与我们的"三列分离"一致

### 7.3 需要纠正（2 条 —— 我们的实测更强）

| # | 文章说法 | 我们的实测 |
|---|---|---|
| 1 | 建议把价格矩阵换成 `open.shift(-1)` | **方向对但不完整**。这不只是"换个价格" —— 它会丢失隔夜跳空的可观测性、且列名会错标（D2）。我们的**三列并列**（`forward_return` / `overnight_gap` / `total_return`）严格更优，能直接回答"因子赚的是哪一段" |
| 2 | 预期"T+1 口径下 IC 绝对值会下降" | **数据不支持**。本次实测 A（T 收盘）与 B（T+1 开盘）口径的 RankIC **差异 < 0.001**。这个直觉在 A 股日线上不成立 —— 值得记进文档，免得后人再按直觉设预期 |

### 7.4 完全缺席（1 条 —— 而它恰恰是我们最核心的）

> **文章通篇没有提「多重假设检验」。**

没有 Bonferroni / BH / BHY，没有 `n_trials`，没有 t > 3.0 基准线。
**而这正是石川书的核心，也是步骤 4 的全部内容，更是 alphalens-cna 区别于
所有现有 A 股 alphalens 改造的地方。**

另外它也**没提六道防线 / 可对拍性** —— 即"怎么知道分析对不对"。

→ 所以：**这篇文章在"工程细节"上很有帮助，在"科学性"上没有增量。**
两者恰好互补，本版路线图已经两边都吸收了。
