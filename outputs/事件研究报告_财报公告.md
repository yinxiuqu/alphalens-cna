# 事件研究（财报公告 · PEAD 检验）报告

**问题**：alphalens 的 event 事件分析能做吗？
**答案**：**能，而且它是所有分析里最简单的一类** —— 本质是"把事件日前后 N 天的收益窗口对齐后取平均"。
本报告用 **83,354 个真实财报公告事件**做了完整实现，并得出一个明确结论。

---

## 一、alphalens 原来是怎么做的

两个入口，底层是同一个函数：

```
create_event_returns_tear_sheet(factor_data, returns, avgretplot=(5,15))
create_event_study_tear_sheet(factor_data, returns, avgretplot=(5,15))
        ↓
perf.average_cumulative_return_by_quantile(factor_data, returns, periods_before, periods_after)
        ↓
perf.common_start_returns(factor, returns, before, after, mean_by_date=True, demean_by=...)
```

`common_start_returns` 的做法（源码）：

```python
for timestamp, df in factor.groupby(level="date"):        # 每个事件日
    day_zero_index = returns.index.get_loc(timestamp)     # 定位
    series = returns.loc[起始:结束, 涉及的股票]              # 切窗口
    series.index = range(起始-事件日, 结束-事件日)          # 对齐到共同相对日
    ...
return pd.concat(all_returns, axis=1)                     # 每个事件一列
```

**要点**：需要 `returns` 是**日频宽表**（日期 × 资产），`before/after` 单位是**交易日**。

## 二、实测：财报公告事件研究

**事件源**：`quantming/data/financial_pit` 的 `ann_314`（财报公告日）
**窗口**：−5 ~ +20 交易日 ｜ **区间**：2020-01 ~ 2026-06
**事件数**：112,038 条公告 → **83,354 个可用窗口**（剔除停牌/边界）
**口径**：**异常收益 = 个股日收益 − 等权市场日收益**（必须去市场，否则结果被大盘涨跌污染）

### 2.1 异常累积收益路径（%）

| 相对日 | 全体 | **超预期** | **平淡** |
|---|---|---|---|
| −5 | 0.000 | 0.000 | 0.000 |
| −3 | +0.049 | +0.221 | −0.124 |
| −1 | +0.312 | **+0.849** | −0.222 |
| **0（公告日）** | +0.218 | **+1.099** | **−0.656** |
| **+1** | +0.192 | **+1.119** | −0.729 |
| +3 | +0.227 | +1.114 | −0.654 |
| +5 | +0.246 | +1.061 | −0.566 |
| +10 | +0.277 | +0.938 | −0.382 |
| **+20** | +0.301 | **+0.862** | **−0.259** |

"超预期/平淡" = 净利润同比增速（缺失用营收增速）高于/低于中位数。

### 2.2 价差路径（超预期 − 平淡）—— 这张表是核心

| 时点 | 价差 |
|---|---|
| 公告前 1 日 | **+1.071%** |
| **公告日当日** | **+1.755%** ← 当天跳升 |
| **公告后 1 日** | **+1.848%** ← **峰值** |
| 公告后 5 日 | +1.627% |
| 公告后 20 日 | +1.121% |

**统计检验**：20 日异常收益 —— 超预期 **+0.909%**（n=41,675）vs 平淡 **−0.321%**（n=41,679），
差异 **+1.230%，t = 11.84 → 高度显著**。

## 三、结论：**不存在 PEAD，反而有公告后反转**

标准 PEAD（财报后漂移）应该表现为"公告后价差**继续扩大**"。
实测是**完全相反**的：

```
公告日跳升 → +1 日见顶 (+1.848%) → 之后单调衰减 → +20 日 (+1.121%)
```

**信息在 1 个交易日内基本被消化完，之后是缓慢回吐。**

同时注意：**公告前 1 日价差已有 +1.071%**（接近公告后 20 日的水平）——
说明要么信息提前泄漏，要么"业绩好的公司股价本来就在涨"（基本面动量）。

## 四、这解释了 ROE 因子为什么没有 alpha

把三份报告串起来看：

| 发现 | 出处 |
|---|---|
| ROE 在月度频率无独立信息（控制规模后 γ=+0.0003, t=0.18） | Fama-MacBeth 报告 |
| 财报信息在**公告后 1 日**就被消化完，之后是衰减 | 本报告 |

**逻辑闭合**：财报信息在**公告当天到次日**就被定价完毕，
而 ROE 是**季度**数据、月度调仓 —— 使用时信息早已反映在价格里。
**所以 ROE 在月频上没有增量 alpha，是结构性的，不是样本问题。**

> 这也提示：**基于财报的因子，其 alpha 窗口可能只有公告日前后 1-2 天**，
> 而不是月度/季度持有期。要做这类因子，必须走**事件驱动**而非**定期调仓**。

## 五、实测发现的命名陷阱（不是数值错误，但会误导）

受控实验（构造"每日恒定 +1%"的数据）：

```
相对日     alphalens 返回     若为累积路径应为
  -5         0.010000           0.0000%
   0         0.010000           5.1010%
  +5         0.010000          10.4622%
```

**`average_cumulative_return_by_quantile` 返回的是「平均日收益」，不是累积路径。**
但它的**函数名和 docstring 都写 "cumulative returns"**。

内部其实是自洽的 —— 绘图函数的 docstring 写的是 "mean daily returns"，
y 轴标签也是 `"Mean Return (bps)"`。**只有函数名和 docstring 错**。

⚠️ **风险**：调用者若按名字理解，会把"日均收益"当成"累积收益"直接汇报。
累积路径必须**自己再 cumprod 一次**（本报告的路径就是自己累积得到的）。

## 六、事件分析的能力清单（对新库的要求）

| 能力 | alphalens | alphalens-cna 应有 |
|---|---|---|
| 窗口对齐平均 | ✅ | ✅ |
| **相对日累积路径** | ⚠️ 需自己 cumprod（命名误导） | ✅ 直接返回，且两种都给 |
| **市场/行业去均值（异常收益）** | 仅 `demean_by`（需自造 DataFrame） | ✅ 内置，一行参数 |
| 按事件特征分组（如业绩惊喜） | 需手工构造 factor | ✅ 原生支持 |
| **显著性检验**（事件组间差异 t 值） | ❌ 无 | ✅ 必须有 |
| 停牌 / 涨跌停 处理 | ❌ 无（窗口内 NaN 直接丢弃） | ✅ 标记并单独统计 |
| 事件日期语义（公告日 vs 可交易日） | ❌ 无 | ✅ 显式区分（T 公告 / T+1 可交易） |
| 多重检验校正 | ❌ 无 | ✅（石川书重点） |

**本次实测又暴露两个 alphalens 的结构性问题**：
1. 事件研究的**去均值**能力太弱（`demean_by` 要手工造 DataFrame），而不去市场均值的结论是错的
2. **完全没有显著性检验** —— 83,354 个事件的差异是否显著，库不管，得自己算
