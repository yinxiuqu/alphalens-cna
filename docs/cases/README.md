# 案例库

这 21 份报告不是文档，是**这个库的开发过程本身**：
每一份都对应一次真实的数据核查或方法争论，每一条结论都能用仓库里的脚本复现。

**它们同时是回归基线** —— 库的改动如果让其中任何一份的数字变了，
要么是 bug，要么是一次需要写进报告的修正。

---

## 一、因子结论（ROE 这条线，改了三次）

| 报告 | 问题 | 结论 |
|---|---|---|
| `ROE因子分析报告.md` / `ROE月度调仓分析报告.md` | ROE 在 A 股有效吗 | 原始口径：RankIC −0.059（252d）、BHY 校正后不显著 |
| `退市股财务补全与存活偏差量化.md` | 补上 250 只退市股会怎样 | \|RankIC\| 反而**弱 20%** —— 因为长持有期的崩盘落在窗口外 |
| `退市收益约定实现与结论修正.md` | 引入退市收益约定 | 均值口径更弱，但尾部口径**变强** |
| `尾部统计与IC盲区.md` | IC 看不见什么 | 最低分位**腰斩率** 4.4% vs 中间 1.7%；秩相关对"联合极值簇"不敏感 |
| `中性化后ROE复核.md` | 是不是市值/行业混杂 | RankIC **符号翻转**（−0.027 → +0.029）；崩盘率结论越控越强（t = −8.28） |

> **收敛结论**：ROE 对收益是（市值中性后）**正向弱因子**；
> 对崩盘是**显著的风险因子**，行业+市值双重中性后 t = −8.28，
> 且通过事前冻结规格的样本外验证。

## 复现方式

| 报告 | 命令 |
|---|---|
| ROE 三口径对照 | `PIT_MODE=delisted+zerofix DELIST_POLICY=last_price python accept_m0.py` |
| 尾部统计 | `python verify_tail.py` |
| 分段稳定性 | `python verify_tail_oos.py` |
| **事前冻结的样本外** | `python verify_oos_prereg.py` |
| 中性化复核 | `python verify_roe_neutral.py` |
| 体检 | `python verify_health.py` |
| 换手口径 | `python verify_turnover.py` |

> 需要 `私有数据仓` 的 PIT 财务表与本地 mongo（`私有数据仓`/`mongodb` 均为私有数据源，
> 适配器在 `examples/`，**不进核心包**）。核心包本身只认契约对象，
> 用 `examples/quickstart.py` 的合成数据即可跑通全流程。
