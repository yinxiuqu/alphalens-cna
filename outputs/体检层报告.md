## 一、这一层做什么

契约层（防线 1）管**结构**：索引、列、有没有前视。
它管不了**内容**：复权算错、整段缺失、股票池只有活着的公司、因子半年没更新 ——
这些数据**结构完全合法**，结论却全错。alphalens 对这类问题一律沉默。

| 检查 | 抓什么 | 硬错误判据 |
|---|---|---|
| OHLC 结构 | `high<low`、`high<max(o,c)`、`low<=0` | 任一行违反 |
| 极端涨跌 | **原始价**日收益 > 50%（A 股制度上限 30%） | 复权后正常 ⇒ `adj_factor` 没盖住除权日 |
| 复权连续性 | 因子倒退、单日跳变 > 2 倍 | 因子倒退（等于负分红） |
| 停牌率 | `volume<=0` 占比 | —（告警） |
| 覆盖率 | 单日股票数相对中位数骤降 | > 5% 交易日都变薄 |
| **存活偏差** | 样本里有没有中途消失的股票 | —（告警） |
| 日历对齐 | 面板日期不在日历上／日频面板有内部空洞 | 日期不在日历上 |
| 因子截面 | 截面唯一值 < 2（算不出 IC） | —（告警） |
| 因子冻结 | 因子值连续 ≥20 期不变 | —（告警） |
| 因子陈旧度 | PIT 陈旧度中位数 > 400 天 | —（告警） |
| 可成交性 | 停牌/涨停/跌停/ST/新股占比 | 某日一只都买不进 |

**五档严重度**：`fail` / `warn` / `info` / `pass` / `skip`。
**缺输入记 `skip`，绝不省略** —— 没查 ≠ 没问题。
**空报告不算通过**（`HealthReport.ok` 要求至少跑了一项）。

已接进 `build_report()`：现在任何一次因子分析的 Markdown 报告
**第二节就是数据体检**，`frames()['health']` 也带得出去。

## 二、第一次真实体检就抓到了真问题 ★

数据：全市场日频行情 + ROE 月度因子（91 个调仓日）。

### 发现 1 · 行情层面的存活偏差（**已修**）

```
⚠️ 存活偏差  5,004 只票**没有一只**在样本中途消失
            —— 这通常意味着股票池是"今天的成分股"或已退市股未入库
```

**根因**（一路查到源头）：

| 事实 | 数字 |
|---|---|
| `stock_day` 里有数据的股票 | 5,905 只 |
| mongo `stock_basic` 标记 `list_status='D'` | 339 只 |
| **`stock_info` 里的退市股** | **0 只**（共 5,066 只，只有在市股） |
| 而 `prep_panel.py` / `prep_open.py` 取代码的方式 | `stock_info.find({})` |
| 结果：缓存面板里的退市股 | **0 / 339** |

退市股 9 月 18 日就入库了（338/339 核实通过），**但分析缓存是 9 月 16 日建的**，
而且建缓存的脚本只认 `stock_info` —— 数据在库里，却从来没进过分析。

**修法**：`_all_codes()` = `stock_info ∪ stock_basic(list_status='D', delist_date ≥ 2016-01-01)`。

| | 修前 | 修后 |
|---|---|---|
| 股票数 | 5,066 | **5,316**（+250 只退市股） |
| 交易日 | 2,600 | 2,604 |
| 体检·存活偏差 | ⚠️ warn（0 只中途结束） | ✅ **pass（242/5,247 = 4.61%）** |

### 发现 2 · 因子层面的存活偏差（**未修，需要补数据**）

行情修好后**重跑 M0 验收，四个数字一字未变**：

```
h= 21  RankIC -0.0111    h= 63  RankIC -0.0223
h=126  RankIC -0.0396    h=252  RankIC -0.0589
```

样本明明多了 250 只票，结论却一模一样 —— 这本身就是证据。查下去：

| 数据源 | 股票数 | 其中退市股 |
|---|---|---|
| PIT 财务表 `financial_pit.parquet` | 5,551 | **0 / 250** |
| mongo `financial` 集合 | 5,565 | **0 / 250** |

**退市股进得了行情截面，进不了 ROE 因子截面** —— 财务数据压根没有它们的记录。
所以 ROE 报告里的那几个 RankIC **仍然是存活偏差下的数字**。

**偏差方向（待验证，现在不下结论）**：退市股多是"低 ROE + 后续暴跌"的公司，
正是"低 ROE → 后续下跌"这条关系最强的样本。把它们排除，
很可能**低估**了 |RankIC| —— 即真实因子强度比 −0.0589 更负。
但这只是方向性推断，**补上数据重跑之前不算结论**。

**下一步**：为 250 只退市股补财务数据（tushare `fina_indicator` / `income` /
`balancesheet` 对退市代码一般仍可取），重建 PIT 表，重跑 M0 验收。

### 发现 3 · `ROE = 0` 占位记录，陈旧度检查抓不到 ★

```
⚠️ 因子冻结  15 只票的因子值连续 ≥20 期不变（最长 42 期）
```

逐条对账后确认**不是本库的 bug**，是 PIT 表的性质：

```
600198（大唐电信）PIT 记录：
   roe = 0.000000   avail_314 = 2019-08-26
   roe = 0.000000   avail_314 = 2019-10-28
   roe = 0.000000   avail_314 = 2020-04-30
   roe = 0.000000   avail_314 = 2021-04-30   ← 10 条 0 值记录，日期各不相同
```

公司停止有效披露后，**源端持续以"新披露"的姿态送来 `roe = 0`**。
后果：因子的 `staleness_days` 始终保持 3–35 天（**陈旧度检查完全抓不到**），
但值连续 32 个月恒为 0 —— **只有冻结检查抓得到**。

影响：每个截面约 0.31% 的假 0 值，且**不随机** —— 集中在不披露的困境公司，
恰恰是 ROE 因子最该识别的那批。

**建议**：PIT 构造时把"连续多期恒为 0"的 `roe` 视为缺失（NaN），而不是 0。

### 发现 4 · 极端涨跌 111 条，全部归因清楚

| | 旧面板 | 新面板（含退市股） |
|---|---|---|
| \|原始收益\| > 50% | 18 条 | **111 条** |
| 其中复权后仍大 | 18 条（100%） | 111 条（100%） |
| 判定 | ⚠️ warn | ⚠️ warn |

新增的 93 条全部来自退市股（退市整理期、重组复牌），**复权后依然大**，
所以判为"可能是真行情"而非"复权错误"。
这条检查的价值在这个**分类**上：若复权后正常（> 80%），直接判 `fail`。

## 三、结论

1. **体检层自己证明了自己的价值** —— 第一次跑真实数据就挖出三个问题，
   其中"行情层面存活偏差"是**已入库的数据从未进入分析**，
   靠肉眼看 IC 数字永远发现不了。
2. **存活偏差被清除了一半**：行情层面已干净（4.61% 中途退市），
   因子层面仍脏（退市股无财务数据）。**ROE 报告的数字暂时不能当作最终结论。**
3. 冻结检查与陈旧度检查是**互补的**，不能只留一个 —— 发现 3 就是反例。
4. M1 剩余：`analysis/regression`（截面回归 / Fama-MacBeth）、
   `analysis/event`（事件研究）、`inference/robustness` + `rank_entropy`、`ledger/`。
