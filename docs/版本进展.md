## 版本号约定

- **patch（0.2.x）**：只做不破坏的修复 —— 装了 0.2.0 的人升级到 0.2.3 不该改代码。
- **minor（0.x+1.0）**：破坏性变更与新功能。
- 例外留档：0.1.4 那次改的是**错误码**（破坏性）却走了 patch —— 那时这条约定还没立起来。
  从 0.1.6 起按上面的规矩走：破坏性变更一律进 minor（0.2.0 就是第一例）。

## 怎么自查

```bash
pytest -q                    # 457 个测试
scripts/ci_local.sh          # ★ 复刻 CI 的依赖集（专治"本地绿、CI 红"，见 README「开发与自检」）
scripts/ci_local.sh --quick  # 跳过对拍 job（不装 alphalens-reloaded）
```

几条**必须守住的**（改错了会被测试直接拦下）：

- `compat.check_parity()` 在退化配置下的最大差**恰好 `0.000e+00`**（不是"接近"）。
- `CleanResult.ledger`：`输入 = 输出 + Σ各类剔除`（清洗层严格对账）。
- 前向收益的已知答案：`forward_return_h(t) = adj_close(t+1+h) / adj_open(t+1) − 1`；
  `total_return_h = (1+forward)(1+overnight_gap) − 1`。
- 报告确定性：同输入两次生成的 markdown **逐字节相同**。

发版流程见 [PyPI 发布步骤](PyPI发布步骤.md)。

## 已知限制（诚实清单）

| 限制 | 说明 |
|---|---|
| **只在一个数据集上做过全量验证** | ROE 因子，800 只 × 5 年 × 60 期。换因子、换数据源仍可能撞出新问题 |
| `exit_policy` 默认 `'assume'` 是**乐观**口径 | 出场日一字跌停照样按当日价成交。真实影响量级取决于实际的出场日一字跌停频率 |
| `dev` extras 不含 pyarrow | `save(kind='frames')` 默认**降级写 CSV**，并在 `save_report['downgraded']` 里逐表说明原因 |
| CI 装的是**最新** pandas/numpy | 实测 CI 上是 pandas 3.0.6 + numpy 2.4.6，本地可能更旧。以 `scripts/ci_local.sh` 为准 |
| 两个台账语义**不同**，别混 | `CleanResult.ledger`（清洗层）严格对账；`Returns.ledger`（收益层）的**原因键可能重叠**（同一行既入场被拦、又出场缺价），恒成立的只有 `dropped = total − tradable` |
| 破坏性变更的历史 | 0.1.4 改过错误码（`nan_p` → `no_valid_p` / `partial_nan_p`）；匹配旧码的 `except` 分支需同步改 |
